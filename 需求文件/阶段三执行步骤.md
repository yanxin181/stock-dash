# 阶段三执行步骤：验证并接入问财数据源

## 目标与边界

在阶段二完成后，验证问财 Skill Hub 的行情查询能力；只有验证通过，才将问财接入大模型模式，作为模拟数据之外的可选数据源。本地模式固定使用模拟数据，大模型模式默认模拟数据。保留无需网络及 API Key 的本地演示。

问财负责提供行情，大模型负责理解需求和组织结论，程序负责校验、数据转换、计算和绘图。数据通过后端按需获取；当前不要求持久化和数据库，也不要求部署远程后端。真实行情接入不意味着实时数据，实际时效、许可与权限以问财服务为准。

## 现状与可行性

- `src/data/stocks.ts` 已提供固定模拟行情；`analyzeDashboard(input, records?)` 已有接收替代行情的入口，可在数据格式和校验适配后复用计算与图表。
- `StockId` 和 `validateDashboardSchema` 目前只接受 A、B；分析文案、看板组件及示例也有“公司”和“模拟数据”等固定显示，需要扩展，不能仅替换数据文件。
- 已发现第三方 TypeScript 项目描述问财 HTTP 调用，但它不是官方契约的替代品。问财 Skill Hub 是否提供可用的逐日历史收盘价与成交量、实际返回格式、Key 权限、调用额度及展示许可尚未实测。不能将其他同花顺产品的 API 当作问财 Skill Hub 的已验证能力。

## 数据与处理流程

```text
大模型模式 + 选择问财 → 输入股票与分析需求
→ 模型生成候选 Schema → 程序校验意图和支持范围
→ 后端解析/确认股票标识 → 请求问财历史行情
→ 校验、标准化并标注实际数据来源及截止时间
→ 现有分析逻辑计算 → 图表、标注和结论使用同一结果
```

程序依据已验证的股票标识和数据结果设置来源、截止日期等可信元信息；不能直接采信模型生成的日期、行情或数据来源。模型只接收完成计算后组织结论所必需的精简事实。

## 步骤 1：验证问财 Skill 与接口（前置关卡）

1. 在问财 Skill Hub 查看“行情数据查询”等相关 Skill 的官方说明，记录版本、安装或调用方式、运行时、认证方式、请求与响应契约，以及与本项目的使用和展示相关的条款。优先从官方资料确认；第三方代码仅作线索。
2. 不在源码、聊天或提交记录中放置真实 Key。按官方说明在本机安全配置问财凭据，确认与模型服务凭据分别管理。不要假设两者通用。
3. 对一只明确的 A 股实际查询最近至少 31 个有效交易日的逐日数据，核实每条是否有股票标识、交易日期、收盘价和成交量；记录字段、单位、价格复权口径、截止时间、时效、排序、分页与错误格式。
4. 再验证双股票、停牌或记录不足、无效股票、无权限、限流和超时等情况；控制请求次数，确认额度和使用条件。不能假定一个自然语言查询一定返回逐日序列，也不能只用单日快照代替历史数据。
5. 如果必须通过 Skill 脚本调用，核对它是否适合由本地 Node 后端安全、可重复调用；若官方提供 HTTP 接口，优先评估直接由后端调用。接口、脚本依赖和权限以实际验证结果为准。

验收关卡：有真实请求及脱敏结果能证明所需字段和口径可用，并确认账号权限与展示许可。若不满足或暂时没有凭据，记录具体缺口、停止问财接入；界面中的问财选项保持“待接入”，阶段二的模拟数据功能不受影响。无凭据时可设计适配接口并用模拟响应测试，但不得宣称真实问财接入成功。

## 步骤 2：扩展股票标识与 Schema

1. 区分模拟标的 A/B 和真实标的的标准代码、显示名称及市场，避免把真实公司代码视作 A/B。名称由可信标的解析结果提供；重名或无法唯一确定时请用户明确选择。
2. 扩展 Schema 类型和统一校验：按数据源校验标的及支持的图表、分析和交易日范围；保持现有模拟示例与规则解析兼容。检查相对走势、分析项与图表之间的跨字段关系。
3. 区分用户请求的截止条件与数据源实际返回的最新日期；`dataSource` 和 `dataAsOf` 必须由程序基于实际结果填充。双股票数据截止日期不同时分别说明，不把共同查询日期冒充每只股票的最新数据日期。
4. 将“模拟数据”“A 公司”等固定文案改为根据实际标的与数据源显示；历史看板保留生成时的来源、名称、日期和复权口径。

验收：原有 5 条模拟示例仍通过；真实股票、非法代码和歧义名称均可正确处理；不存在把模拟数据标为问财数据的情况。

## 步骤 3：实现后端问财适配器

1. 增加数据源接口和问财适配器；前端仅调用本地后端，问财 Key 存放于后端环境配置。配置示例不含真实密钥。
2. 只根据经过校验的股票、日期及字段构造受支持请求；限制输入、返回量及超时，处理认证、无权限、限流、额度不足、网络错误和上游异常。不要把用户输入直接拼成 shell 命令，也不要泄露密钥。
3. 将实际返回结果转换为项目内部统一结构：股票标识、交易日期、收盘价、成交量及可信来源元信息；按实际契约转换单位，明确价格复权口径。不将缺失、无效或不可解析的值当作零。
4. 校验数据类型、日期、重复记录、标的归属、单位及数量；按日期排序。分页是否需要以及缺失字段如何处理以实测接口为依据。保留脱敏的可复现测试样本，不将未获授权数据或敏感信息写入仓库。

验收：真实查询可返回经过校验的内部结构；接口失败有清楚的中文提示，不静默切换到模拟数据。

## 步骤 4：处理交易日与计算口径

1. “最近 N 个交易日”依据实际返回的有效交易记录截取。需要每日涨跌幅时，额外获取区间首日之前的有效前收盘价；数据不足时有限扩大查询范围，仍不足则提示，不能无限重试或伪造数据。
2. 确认停牌、节假日、上市不足 N 天及缺失日期的返回规则。双股票按日期对齐，缺失值保持为空；交易记录与交易所日历不一致时如实提示，不猜补价格。
3. 明确除权除息与复权口径：对比数据源提供的前收盘价或涨跌幅定义，决定何时可用相邻收盘价计算；若无法保证一致，提示该指标不可用，不展示误导性结果。区间涨跌幅、相对走势按所选一致价格口径计算并展示。
4. 图表、排名和结论共享同一份标准化数据和计算结果；数据显示实际截止日、来源、价格口径、成交量单位及必要的延迟说明。

验收：正常行情、首日前值缺失、停牌或双股票日期不齐、数据不足与除权情形都有明确结果或提示；数值和数据源口径可核对。

## 步骤 5：接入界面与追问

1. 步骤 1 验证通过并实际实现后，启用大模型模式下的“问财数据”选项；本地模式仍固定模拟数据。数据源不可用时提示原因，不以“已连接”代替实际请求状态。
2. 切换数据源不自动更改已有看板；历史看板保留自己的来源与截止时间。在新数据源上追问时重新确认标的兼容性、重新获取数据并计算；例如模拟 A/B 无法自动映射为真实公司，应要求用户指定真实股票。
3. 提供获取行情、处理数据、生成结论等实际状态。任何解析、获取、校验或计算失败时保留旧看板；结论生成失败则使用同一计算结果的模板结论。
4. 模型 Key 与问财 Key、网络及额度分别提示；页面显示真实来源和适当的时效说明，不将数据标签硬编码为“模拟数据”。

验收：切换模式和数据源符合约定；真实与模拟看板来源准确；请求失败或追问不兼容时不破坏历史看板。

## 步骤 6：测试与交付

1. 自动化测试使用模拟的问财响应，覆盖字段转换、单位、数据缺失、重复日期、分页（如适用）、股票校验、交易日截取、前值、双股票对齐及错误处理；继续运行现有测试和构建。
2. 人工验证一只股票的 30 天股价/成交量和涨跌幅，再验证两只股票对比、标注与追问；对照实际接口响应核对日期、值、单位与数据来源。记录测试时间与数据口径，不将模拟响应测试称为真实接入验证。
3. 检查无 Key、无网络及后端关闭时本地模式仍可完整演示；问财请求失败必须明确提示。
4. 更新 README：数据源切换、问财配置与启动、依赖、权限与费用说明、支持范围、复权和单位、数据时效、失败行为、已知限制及实际验证结论。交付源码与无密钥配置示例；问财不可用时如实标注未接入及原因。

## 完成标准

- 问财关键能力和账户权限已实际验证；大模型模式可按约定选择模拟或问财数据，真实看板正确展示来源、时间和口径。
- 图表和结论基于同一份经验证、标准化的行情；失败和缺失数据处理明确，旧看板不被破坏。
- 本地模式无网络、无 Key 仍可运行；模拟数据始终完整可用。
- 自动化测试和构建通过，README 如实记录真实验证结果。如果前置关卡未通过，阶段三交付验证报告与限制说明，而不是宣称问财数据源已接入。
