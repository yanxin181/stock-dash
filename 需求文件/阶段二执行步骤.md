# 阶段二执行步骤：大模型模式

## 目标与范围

在现有本地模式上增加大模型模式：模型理解首次输入和简单追问，生成看板 Schema，并根据程序算出的结果组织简短结论。两种模式共用 Schema 校验、固定模拟数据、计算及图表组件。本地模式保持离线可用；本阶段不需要数据库，也不接入真实行情。

分析模式和数据源分别选择：本地模式固定使用模拟数据；大模型模式可选择模拟数据或问财数据。问财能力的验证和实际接入属于阶段三；阶段二先完成数据源选项和状态设计，其中问财选项标记为“待接入”并禁用，不得伪装成真实行情。大模型模式默认选择模拟数据。

技术选型：Vue 3 + TypeScript + Vite、Node.js + Express + TypeScript、现有手写 Schema 校验和 Vitest。模型服务商、模型名称及具体 SDK 待确定；通过后端环境变量配置，不将密钥放入前端或版本库。

## 前端、后端、模型的分工

| 参与方 | 职责 |
| --- | --- |
| 前端代码 | 模式切换、输入和处理状态；保存当前有效 Schema；调用后端；校验候选 Schema；调用现有计算逻辑；渲染图表和结论；失败时保留原看板。 |
| 后端代码 | 读取密钥和模型配置；提供解析及结论接口；校验请求、控制请求大小与超时；调用模型并检查响应格式；返回可理解的错误，不暴露密钥。 |
| 大模型 | 将首次输入转换为候选 Schema；结合当前 Schema 理解追问并提出修改；根据程序给出的事实选择、组织简短结论。模型结果均视为不可信输入。 |
| 程序共同负责 | 使用同一校验规则检查 Schema；由代码筛选固定数据、计算数值、生成图表与模板结论；对模型结论进行一致性控制。 |

模型不直接读取密钥、执行代码、查询真实行情或计算最终图表数据；不编造原因、预测或数据。支持范围仍受现有 Schema、内置数据和校验规则约束。

## 处理流程

```text
首次输入或追问 + 当前有效 Schema（仅追问时）
    → 前端请求本地后端 → 后端请求模型 → 候选 Schema 或需澄清提示
    → 程序补充可信的数据来源与截止日期 → 校验 Schema
    → 现有分析代码筛选并计算 → 图表与模板结论
    → 将精简的计算事实交给模型 → 校验/组装结论，失败则使用模板
    → 渲染看板；计算成功后提交当前有效 Schema
```

模型解析与结论通常各调用一次；结论调用失败不影响已经成功计算的看板。不要把所有历史消息或全部行情传给模型，仅发送必要的当前 Schema、输入和结论所需事实，以控制费用。模型输出可能不稳定；本地模式保持可复现。

## 步骤 1：模式和界面状态

1. 将左下角和右上角的固定文案绑定到当前选择的模式：本地模式显示“本地演示环境 / 模拟数据 · 无需联网”和“本地环境”；大模型模式显示“大模型环境 / 模拟数据 · 需要联网”和“大模型环境”。
2. 环境名称仅表示当前选择，并不代表连接成功；如显示连接状态，应单独依据实际请求结果展示，不能将选中模式当作已连接。
3. 发送中禁用模式切换；按每条消息实际生成时的模式标注，避免切换后历史消息标签变化。切换模式保留当前有效看板和 Schema，允许在另一模式下继续追问。
4. 增加数据源选择：本地模式显示并固定为“模拟数据”；大模型模式提供“模拟数据”和“问财数据”，其中问财在阶段三验证并接入前标记“待接入”且不可选。切回本地模式时数据源同步设为模拟数据；再次进入大模型模式默认使用模拟数据。发送中禁用数据源切换。
5. 数据源切换不自动重算或改写已有看板；每个看板保留实际生成时的数据来源和截止时间。阶段三接入后，使用另一数据源追问时须重新校验股票等配置并用新数据重新计算，若不兼容则提示并保留旧看板。获取问财失败时明确报错，不静默显示模拟数据。

验收：切换时两个位置同步更新，切回本地恢复原文案；本地模式仅使用模拟数据，大模型模式默认模拟数据且问财选项在接入前不可选；请求进行中和失败后状态准确，历史看板来源不随选择改变。

## 步骤 2：建立本地后端

1. 新建 Express + TypeScript 服务，提供例如 `POST /api/schema` 和 `POST /api/conclusion` 的接口；前端开发时通过 Vite 代理访问，避免硬编码服务地址。
2. 配置模型服务地址、模型名称、API Key、端口及超时；提供无真实密钥的 `.env.example`，忽略真实环境文件。将绑定地址默认限制为本机，接口响应和日志不输出密钥或上游敏感详情。
3. 对输入长度、JSON 结构和必要字段做限制；处理配置缺失、超时、额度不足、网络失败和上游无效响应。建立开发、测试和构建命令，并提供一条命令启动前后端。
4. 依据服务商实际能力选择 SDK 或 HTTP 接口；不得假定所有服务商都支持相同的结构化输出功能。

验收：无 Key 时后端返回清楚的配置提示；前端仍可独立使用本地模式。模拟上游调用即可测试接口，无须消耗真实额度。

## 步骤 3：首次需求生成 Schema

1. 把用户输入和支持范围、字段定义、示例、输出格式发给模型，要求返回候选 Schema，或在不支持、信息不足、存在歧义时返回可展示的提示。
2. 让程序根据固定数据设置可信的数据来源和截止时间，不采信模型猜测。后端检查响应结构，前端使用现有 `validateDashboardSchema` 校验，再调用 `analyzeDashboard` 计算；需要时在后端复用同一校验器，避免两套规则分叉。
3. 拒绝无效 JSON、非法股票、指标、单位、日期及不受支持的组合；不能静默猜测或渲染无效结果。检查现有校验器是否覆盖必要的跨字段关系，并补齐缺口。

验收：5 条示例生成的 Schema 均符合用户意图且通过校验；不支持的股票、指标和缺失信息均给出明确提示。测试使用固定模拟模型响应，不要求模型每次输出完全相同。

## 步骤 4：大模型理解追问

1. 将追问与当前有效 Schema 一同提供给模型；模型返回完整候选 Schema，或返回需要澄清/不支持的提示。保留未要求修改的条件，并使相关图表、分析配置和标题保持一致。
2. 首次输入和追问需有明确判断：存在当前看板时允许模型区分新需求与追问，但不能仅因存在历史看板就把所有输入当作追问；无法判断或目标不明确时提示用户补充。
3. 程序重新填充可信数据元信息、校验、计算；仅当全部成功后更新当前 Schema。失败时保留旧看板和追问依据。
4. 至少覆盖“把成交量改成涨跌幅”“改为最近 10 个交易日”，并增加如“时间缩短到十天”“把量换成每天涨跌”的语义表达；“改成柱状图”遇到多张候选图时应要求指明目标。

验收：正确保留未修改的股票、范围及其他条件；模糊目标、非法修改和模型故障均不会破坏旧看板。阶段二不要求完整多轮对话记忆。

## 步骤 5：生成与图表一致的结论

1. 继续由现有分析代码产出计算结果和模板结论；从同一份结果提取带单位、日期和股票标识的精简事实。
2. 为可靠性，优先让模型返回受限的结构化表达方案，例如选择事实 ID 和表述模板；由程序验证引用和语义后填入数值、单位及日期。对无法验证的自由文本，不作为可信模型结论展示，直接使用模板结论。验证须覆盖方向、比较对象、时间和数值，不仅检查数字是否出现。
3. 不允许模型添加未提供的涨跌原因、预测或建议。模型请求失败、输出无效、引用不存在的事实或语义无法确认时，采用模板结论并给出适当提示。

验收：结论和当前图表共享同一次计算结果；注入错误数值、方向、股票或日期时不会展示错误结论；模型调用失败仍能展示看板及模板结论。

## 步骤 6：异常处理与状态

1. 显示实际步骤：理解需求/生成 Schema、校验 Schema、处理数据、生成结论、渲染图表；不要显示尚未执行的步骤。
2. 区分输入无效、后端未启动、密钥缺失、网络或超时、额度不足、模型输出无效、Schema 校验失败和数据处理失败，给出可操作的提示；不泄露密钥。
3. 解析失败时保留旧看板；结论失败时保留新看板并使用模板。提供切换本地模式的路径，不自动把模型失败伪装成模型成功。

## 步骤 7：测试、交付与验收

1. 自动化测试：接口使用模拟模型，覆盖成功、超时、配置缺失、无效输出；覆盖 Schema 校验、追问保留条件和失败回退；覆盖结论事实引用及方向错误。继续运行现有测试和构建。
2. 人工检查：两种模式的界面文案；5 条示例；两类必需追问及模糊追问；后端关闭、无 Key、断网、额度用尽等情况。断网且无 Key 时验证本地模式完整可用。
3. 在有有效 Key 和网络时做少量真实模型冒烟测试，记录模型及结果；无法测试时如实记录，不把模拟测试当作真实接入验证。
4. 更新 README：Node 版本、安装和启动、环境变量示例、模型服务配置、费用和非确定性、失败回退、数据口径及已知限制。交付源码和无密钥示例配置；接收者安装依赖并自行配置 Key。真实密钥不得提交或打包。

## 完成标准

- 本地模式离线可演示；大模型模式在后端、网络及配置可用时可完成输入、Schema 生成、计算、图表、结论和一次追问。
- 左下角、右上角随选定模式同步；状态不冒充连接成功。
- 数据源选择符合模式约束；问财在阶段三接入前明确标记且不可选，模拟数据始终完整可用。
- 程序负责校验和所有行情计算，图表与结论数据一致；模型输出无效时有清楚提示或安全回退。
- 自动化测试与构建通过，README 足以让接收者配置并运行；不需要数据库或部署远程后端。
