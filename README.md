# 问数：自然语言股票分析看板

输入一句分析需求，系统将其转换为可视化 Schema，校验后使用项目内置的模拟股票数据生成图表和分析结论。项目支持本地规则解析和大模型解析两种模式，图表与结论共用程序计算结果。
设置*本地模式*和*大模型模式*，本地模式根据规则分析需求，大模型模式有千问大模型把自然语言转换为Schema。

## 运行方法

### 1. 环境准备

- Node.js 20.19 及以上，或 22.12 及以上；推荐使用 Node.js 22 LTS。
- npm，以及现代浏览器。

在项目根目录安装依赖：

```bash
npm install
```

### 2. 启动本地模式

```bash
npm run dev
```

打开终端显示的地址，通常是 `http://127.0.0.1:5173/`。如果端口被占用，请使用终端显示的实际地址。依赖安装完成后，本地模式无需启动后端、联网或配置 API Key。

### 3. 启动大模型模式


编辑项目根目录的 `.env`，填写自己的阿里云百炼 API Key（已填写可以直接使用，或者替换成自己的，已限制额度）：

```env
DASHSCOPE_API_KEY=在此填写自己的密钥
MODEL_NAME=qwen3.7-flash
MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MODEL_TIMEOUT_MS=30000
PORT=4174
```

然后启动前端和后端：

```bash
npm run dev:all
```

打开终端显示的前端地址，在输入框左侧选择「大模型模式」。后端默认只监听 `127.0.0.1:4174`，开发前端通过 Vite 代理访问后端。使用大模型需要网络、有效的百炼 Key 和模型权限；模型调用可能产生费用，结果也可能因调用而不同。API Key 应与所配置服务地址的地域一致。修改配置后请重启服务。

`.env` 仅用于本机配置，不要提交或分享；仓库中只保留无密钥的 `.env.example`。如果系统环境变量已经设置相同配置项，后端会优先使用系统环境变量。

### 4. 测试与构建

```bash
npm test              # 运行 Vitest 测试
npm run build         # 类型检查并构建前端和后端
npm run dev:server    # 单独启动后端开发服务
npm run start:server  # 启动已构建的后端，需先执行 npm run build
```

在运行服务的终端按 `Ctrl + C` 可以停止服务。自动化测试使用固定数据和模拟上游响应，不代表真实模型调用已经通过验证。

## 已实现功能

- **自然语言输入与示例**：首页提供 6 条可点击的示例，可输入 A、B 公司最近 2～60 个交易日的分析需求。
- **两种分析模式**：本地模式按固定规则解析；大模型模式通过后端调用百炼，生成候选 Schema 或澄清提示。两种模式共用 Schema 校验、模拟数据、计算和图表。
- **图表与指标**：支持收盘价、成交量、每日涨跌幅、双公司相对股价和 5 日均线；支持折线图、柱状图、涨跌天数环形图、成交量与每日涨跌幅散点图。
- **分析与结论**：支持最高最低收盘价、最大单日涨幅、跌幅排名、成交量排名和区间涨跌幅。大模型模式下，程序从同一次计算结果生成比较事实，模型建议呈现顺序；程序校验引用并补回遗漏事实，不采用模型自由编写的数值或预测。
- **简单追问**：可在有效看板上修改时间、指标或图表类型等；本地模式使用有限的关键词规则，大模型模式支持部分更灵活的表达。多图时需要说明修改目标。
- **状态与错误处理**：显示当前处理阶段；解析或校验失败时保留旧看板，模型结论失败时保留新看板并使用模板结论，也可切换到本地模式。

本地模式的完整关键词、可复制示例和追问限制见 [图表关键词与测试指令](需求文件/图表关键词与测试指令.md)。例如：

```text
分析 A 公司最近 30 个交易日的股价和成交量，并标出跌幅最大的 3 个交易日。
```

成功生成看板后，可继续输入 `改为最近 10 个交易日` 或 `把成交量改成涨跌幅`。

## 数据口径

- 模拟数据位于 `src/data/stocks.ts`，包含 A、B 两家公司各 61 条记录，日期范围为 2025-11-07 至 2026-01-30。日期按周一至周五生成，未排除节假日。
- 价格为模拟收盘价，单位为元；成交量单位为万股。最近 N 个交易日以数据截止日期为基准，不代表当前行情。
- 每日涨跌幅 =（当日收盘价 − 前一交易日收盘价）/ 前一交易日收盘价 × 100%；前值缺失或为零时不计算，也不参与相关统计和排名。
- 区间涨跌幅以所选区间首日收盘价为基准；双公司相对走势分别以各自区间首日为 100 基准点。基准价格为零时无法计算。
- 5 日均线取当日及之前 4 个交易日的收盘价平均值，可使用区间前的已有数据；不足 5 条时留空。涨跌天数环形图和量价散点图排除每日涨跌幅不可用的日期；散点关系不代表因果关系。

## 实现流程

```text
用户输入
  → 本地规则解析 / 后端调用模型
  → 候选 Schema → 程序填充可信数据来源和截止日期 → Schema 校验
  → 筛选并计算模拟数据 → 图表、排名和模板结论
  → 大模型模式：模型建议事实顺序，程序校验并组装结论
  → 展示看板；计算成功后更新当前有效 Schema
```

`src/types/schema.ts` 定义 Schema，`src/services/validateSchema.ts` 负责运行时校验，`src/examples/schemas.ts` 保存 6 条输入及对应的预期 Schema。测试覆盖正常解析、非法 Schema、计算、追问、模型错误和结论回退。

## 已知限制

- 看板目前只使用内置模拟数据，支持 A、B 公司，不提供真实行情、投资建议或行情预测。
- 本地模式只识别有限句式；大模型的需求理解存在不确定性，不提供完整多轮记忆。模型输出必须通过程序校验。
- 结论由程序根据计算事实生成，模型不自行计算行情；模型调用失败时使用本地模板结论。
- 后端提供 `POST /api/wencai/quotes` 用于问财查询验证，使用独立的 `IWENCAI_API_KEY`；**该接口尚未接入看板**。返回数据的成交量单位、价格复权口径及展示许可仍待确认，详见 [阶段三步骤 1 验证记录](需求文件/阶段三步骤1验证记录.md)。
- 问财及大模型接口都需要各自有效的服务配置和网络；不要在源码、截图或提交文件中包含真实密钥。
