# 问数：股票分析对话 MVP

本项目实现阶段一的最小对话切片：本地规则识别、固定模拟数据计算、对话气泡和回复，支持选择本地模式或大模型模式。大模型模式目前只展示未接入提示。对话页面已接入 Schema 校验、本地计算与图表看板；大模型、问财及阶段一的完整验收尚未完成。

## 运行

需要 Node.js。首次运行 `npm install`，随后运行 `npm run dev` 并打开终端给出的本地地址。运行 `npm test` 执行测试，`npm run build` 构建。依赖安装完成后，本地分析不需要网络或 API Key。

## 数据与能力

数据为项目内固定记录，范围为 2025-11-07 至 2026-01-30，每家公司 61 条模拟交易日记录（按周一至周五生成，未排除节假日）；价格为模拟收盘价（元），成交量单位为万股。支持 A、B 公司及 2–60 个交易日。每日涨跌幅 =（当日收盘价 − 前一交易日收盘价）/ 前一交易日收盘价；区间涨跌幅以区间首日为基准。上一条有效需求可用于“改为最近 10 个交易日”或“把成交量改成涨跌幅”等简单追问，无法识别的追问不会覆盖它。界面内示例可点击填入并发送。

规则识别仅覆盖有限表达方式，不连接真实行情，不支持预测；结果仅用于演示。问财 Skill 尚未调研或接入。

## 数据与 Schema 定义（步骤二）

- `src/data/stocks.ts` 为固定模拟行情，每条记录包含公司标识、日期、收盘价（元）和成交量（万股）；每家公司按日期升序排列。61 条数据覆盖最近 30 个交易日及其前一交易日。数据不代表真实行情。
- `src/types/stock.ts` 和 `src/types/schema.ts` 定义数据及看板 Schema；`src/examples/schemas.ts` 给出五条需求各自的预期 Schema。示例 5 的相对走势以各自区间首日为 100，单位为基准点。
- 最近 N 个交易日以数据截止日为基准，取不晚于截止日的最近 N 条。每日涨跌幅 =（当日收盘价 − 前一交易日收盘价）/ 前一交易日收盘价 × 100%；前值缺失或为零时无可用值且不参与排名。区间涨跌幅 =（区间末日收盘价 − 区间首日收盘价）/ 区间首日收盘价 × 100%；首日价格为零时无法计算。相对走势 = 当日收盘价 / 该股票区间首日收盘价 × 100，缺失值不按零处理。跌幅排名仅包含实际下跌日。
- Schema 类型、校验、解析和计算已接入对话页面。

## Schema 校验（步骤三）

`src/services/validateSchema.ts` 的 `validateDashboardSchema` 接收不可信输入（`unknown`），成功时返回 `{ success: true, data }`，失败时返回 `{ success: false, errors }`，每条错误包含字段路径 `path` 和中文提示 `message`。校验股票、日期、2–60 个交易日、图表指标与单位、分析类型和排名数量等。排名数量大于实际可用条数时仍为合法配置，后续计算须如实展示已有结果。数据是否存在及实际可计算性由后续数据处理负责。

本地解析和计算均使用该校验器；后续大模型输出也应先通过校验。

## 本地指令解析（步骤四）

`src/services/parseInstruction.ts` 的 `parseInstruction` 将支持的自然语言指令转换为 Schema，并调用 `validateDashboardSchema`。返回成功结果含 `schema`；失败结果包含失败步骤和提示，校验失败时附字段错误。支持 A、B 公司、2–60 个交易日、股价、成交量、每日涨跌幅、最高最低价、最大涨幅、跌幅和成交量排名，以及明确指定折线图或柱状图；双股票股价对比使用首日为 100 的相对走势。输入须写明股票和交易日范围；尚不支持的文字不会静默忽略。

对话页面使用该解析服务生成 Schema，再执行本地计算并渲染看板。

## 数据筛选与分析（步骤五）

`src/services/analyzeDashboard.ts` 的 `analyzeDashboard(schema, records?)` 先校验 Schema，再按股票及截止日期排序并截取最近 N 条；可选 `records` 用于替换数据源和测试。成功时返回筛选后的数据、按日期对齐的图表序列、标注及排名、模板结论和提示；这些结果共享同一次计算。失败时返回步骤与错误信息。对话页面和图表组件使用该服务结果。

每日涨跌幅使用所选首日之前的上一条交易记录；前值缺失或为零时返回 `null`，不参与排名。涨幅排名只包含正涨幅，跌幅排名只包含负涨幅；符合条件不足时报告实际数量。相同数值按日期升序排列。双股票日期不齐时按日期并集对齐，缺失数据为 `null`，并提示两者各自首日可能不同；每家公司以自身区间首日为 100。区间首价为零时，相对走势和区间涨跌幅返回 `null` 并提示。图表数据保留计算精度，文字结论显示两位小数。数据不足时返回实际条数及提示，某只股票完全无数据则返回错误。

## 页面与图表（步骤六）

对话页面将本地需求依次送入解析、校验与计算服务，并使用 ECharts 展示折线图或柱状图、分析排名、标注、结论及数据来源。图表与文字来自同一份计算结果；处理失败时对话中显示具体提示，已有看板保留。大模型模式仍未接入。支持在当前有效看板上进行简单追问。

## 看板追问（步骤七）

生成本地看板后，可输入“改为最近 10 个交易日”或“把成交量改成涨跌幅”。前者保留股票、图表和分析要求；后者保留股票、时间范围和其他指标，将成交量图表替换为每日涨跌幅，并移除不再适用的成交量排名。交易日范围支持 2–60 天。

`src/services/followUp.ts` 基于当前有效 Schema 生成新配置，先重新校验，再交由数据分析服务计算；只有全部成功才更新当前配置。无原看板、没有成交量图表、范围非法或追问无法识别时会提示，保留之前的看板及后续追问依据。该功能针对上述两类简单追问，不提供完整多轮语义理解。
