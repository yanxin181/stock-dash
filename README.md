# 问数：股票分析对话 MVP

本项目支持本地规则识别和大模型理解完整需求及简单追问，通过统一 Schema 校验、固定模拟数据计算和图表看板展示结果。大模型可对计算事实建议呈现顺序；问财数据尚未接入。

## 运行

需要 Node.js 20.19+ 或 22.12+（推荐 Node.js 22 LTS）。首次运行 `npm install`。`npm run dev` 单独启动前端，本地模式不需要后端、网络或 API Key；`npm run dev:all` 同时启动前端和本地后端，打开终端给出的前端地址。运行 `npm test` 执行测试，`npm run build` 构建前后端；构建后可使用 `npm run start:server` 单独启动后端。

## 阶段二本地后端

将 `.env.example` 复制为 `.env`，在阿里云百炼控制台创建 API Key 并设置 `DASHSCOPE_API_KEY`。默认模型为 `qwen3.7-flash`，默认服务地址为百炼北京地域的 OpenAI 兼容接口；也可设置 `MODEL_BASE_URL` 为同地域业务空间的 HTTPS 兼容接口地址，设置 `MODEL_NAME`、`MODEL_TIMEOUT_MS`（1000–120000 毫秒）和后端 `PORT`。API Key 必须与服务地域匹配。`.env` 不提交版本库，不要把密钥放在前端。使用模型会产生费用，输出具有不确定性。

后端默认仅监听 `127.0.0.1:4174`，Vite 将 `/api` 请求代理到同一端口。`POST /api/schema` 接受 `{ "input": "分析 A 公司", "currentSchema": ... }`（`currentSchema` 可省略），返回候选 Schema 或澄清提示；`POST /api/conclusion` 接受 `{ "facts": [{ "id": "1", "text": "事实" }] }`，返回模型选择的事实 ID。接口限制请求大小和输入长度，检测上游 JSON 和响应结构；候选 Schema 仍须在使用前完整校验，事实引用也需由后续结论流程结合语义进行验证。无 Key 时返回明确配置错误；超时、鉴权、额度、网络及格式错误均返回分类提示，不转发上游详情。

大模型模式支持完整需求和基于当前有效看板的简单追问，只发送当前 Schema 和本次输入，不发送完整对话或全部行情。模型区分新需求与追问，返回候选 Schema 或澄清提示；程序覆盖数据来源及截止日期、校验并计算看板，成功后才更新当前配置。解析失败时保留已有看板。结论请求仅发送从同一次计算结果生成的比较事实，模型建议事实编号的顺序；程序负责全部表述和数值，并补回模型遗漏的图表与分析事实。请求失败或模型返回无效内容时，新看板仍会显示，并提示使用本地模板结论。多图追问须指明目标，模型对意图的理解具有不确定性，无法判断时应补充说明。自动化测试通过模拟上游完成，不代表已验证真实 Key、网络或模型效果。问财数据仍未接入。

处理时界面显示当前正在执行的阶段。输入无效、后端不可达、Key 缺失或鉴权失败、网络或超时、额度限制、模型输出无效、Schema 校验和数据处理失败会分别提示处理方向；模型请求失败时可使用提示旁的“切换本地模式”，不会自动伪装为本地模式成功。

## 数据与能力

数据为项目内固定记录，范围为 2025-11-07 至 2026-01-30，每家公司 61 条模拟交易日记录（按周一至周五生成，未排除节假日）；价格为模拟收盘价（元），成交量单位为万股。支持 A、B 公司及 2–60 个交易日。每日涨跌幅 =（当日收盘价 − 前一交易日收盘价）/ 前一交易日收盘价；区间涨跌幅以区间首日为基准。上一条有效需求支持修改时间、指标、图表类型、分析要求和股票；无法识别或处理失败的追问不会覆盖它。界面内示例可点击填入并发送。

规则识别仅覆盖有限表达方式，不连接真实行情，不支持预测；结果仅用于演示。问财 Skill 已完成单股和双股真实查询的初步验证，但数据口径、展示许可等尚未确认，因此仍未接入；具体结果和缺口见 [阶段三步骤 1 验证记录](需求文件/阶段三步骤1验证记录.md)。

## 扩展指标和图表

首页可选择“均线、涨跌分布与量价关系”示例，展示股价与 5 日均线折线图、上涨/下跌/持平天数环形图，以及成交量与每日涨跌幅散点图。本地模式和大模型模式均可解析该完整示例。

5 日均线是当日及之前 4 个交易日收盘价的算术平均，会使用所选区间之前已有的历史记录；不足 5 条时显示为空并提示。环形图将每日涨跌幅大于、等于或小于零的有效交易日分别计数，缺少前一日收盘价或前收盘价为零时排除并显示不可计算天数。散点图以成交量（万股）为横轴、每日涨跌幅（%）为纵轴，排除相同的不可计算日期；它展示对应关系，不代表因果关系。图表数据和结论均来自同一次计算，仍为内置模拟数据。

## 数据与 Schema 定义（步骤二）

- `src/data/stocks.ts` 为固定模拟行情，每条记录包含公司标识、日期、收盘价（元）和成交量（万股）；每家公司按日期升序排列。61 条数据覆盖最近 30 个交易日及其前一交易日。数据不代表真实行情。
- `src/types/stock.ts` 和 `src/types/schema.ts` 定义数据及看板 Schema；`src/examples/schemas.ts` 给出五条需求各自的预期 Schema。示例 5 的相对走势以各自区间首日为 100，单位为基准点。
- 最近 N 个交易日以数据截止日为基准，取不晚于截止日的最近 N 条。每日涨跌幅 =（当日收盘价 − 前一交易日收盘价）/ 前一交易日收盘价 × 100%；前值缺失或为零时无可用值且不参与排名。区间涨跌幅 =（区间末日收盘价 − 区间首日收盘价）/ 区间首日收盘价 × 100%；首日价格为零时无法计算。相对走势 = 当日收盘价 / 该股票区间首日收盘价 × 100，缺失值不按零处理。跌幅排名仅包含实际下跌日。
- Schema 类型、校验、解析和计算已接入对话页面。

## Schema 校验（步骤三）

`src/services/validateSchema.ts` 的 `validateDashboardSchema` 接收不可信输入（`unknown`），成功时返回 `{ success: true, data }`，失败时返回 `{ success: false, errors }`，每条错误包含字段路径 `path` 和中文提示 `message`。校验股票、日期、2–60 个交易日、图表指标与单位、分析类型和排名数量等。排名数量大于实际可用条数时仍为合法配置，后续计算须如实展示已有结果。数据是否存在及实际可计算性由后续数据处理负责。

本地解析和计算均使用该校验器；后续大模型输出也应先通过校验。

## 本地指令解析（步骤四）

`src/services/parseInstruction.ts` 的 `parseInstruction` 将支持的自然语言指令转换为 Schema，并调用 `validateDashboardSchema`。返回成功结果含 `schema`；失败结果包含失败步骤和提示，校验失败时附字段错误。支持 A、B 公司、2–60 个交易日、股价、成交量、每日涨跌幅、最高最低价、最大涨幅、跌幅和成交量排名，以及明确指定折线图或柱状图；双股票股价对比使用首日为 100 的相对走势。输入须写明股票和交易日范围；尚不支持的文字不会静默忽略。

对话页面使用该解析服务生成 Schema，再执行本地计算并渲染看板。

## 数据筛选与分析（步骤五）

`src/services/analyzeDashboard.ts` 的 `analyzeDashboard(schema, records?)` 先校验 Schema，再按股票及截止日期排序并截取最近 N 条；可选 `records` 用于替换数据源和测试。成功时返回筛选后的数据、按日期对齐的图表序列、标注及排名、模板结论和提示；这些结果共享同一次计算。失败时返回步骤与错误信息。对话页面和图表组件使用该服务结果。

每日涨跌幅使用所选首日之前的上一条交易记录；前值缺失或为零时返回 `null`，不参与排名。涨幅排名只包含正涨幅，跌幅排名只包含负涨幅；符合条件不足时报告实际数量。相同数值按日期升序排列。双股票日期不齐时按日期并集对齐，缺失数据为 `null`，并提示两者各自首日可能不同；每家公司以自身区间首日为 100。区间首价为零时，相对走势和区间涨跌幅返回 `null` 并提示。图表数据保留计算精度，文字结论显示两位小数。数据不足时返回实际条数及提示，某只股票完全无数据则返回错误。

## 页面与图表（步骤六）

对话页面将需求依次送入解析、校验与计算服务，并使用 ECharts 展示折线图或柱状图、分析排名、标注、结论及数据来源。图表与文字来自同一份计算结果；处理失败时对话中显示具体提示，已有看板保留。本地模式支持在当前有效看板上进行简单追问。

## 看板追问（步骤七）

生成本地看板后，可追问修改交易日范围、切换指标与图表类型、增加最高最低价或调整跌幅排名，也可替换公司或增加公司进行对比。交易日范围支持 2–60 天。完整支持句式、限制和连续测试指令见 `需求文件/图表关键词与测试指令.md`。

`src/services/followUp.ts` 基于当前有效 Schema 生成新配置，先重新校验，再交由数据分析服务计算；只有全部成功才更新当前配置。无原看板、没有成交量图表、范围非法或追问无法识别时会提示，保留之前的看板及后续追问依据。该功能按关键词识别，不提供完整多轮语义理解。


## 问财后端查询（验证中）

后端已提供 `POST /api/wencai/quotes`，接收例如 `{"stocks":["600519.SH"],"count":30}`；支持 1–2 个带市场后缀的股票代码及 2–60 个交易日。它向问财请求多一个交易日，校验股票、日期和数值后返回按日期排序的数据。问财 Key 使用独立的 `IWENCAI_API_KEY` 环境变量，也可由使用者在不提交的 `.env` 文件中配置；不要将真实 Key 打包或提交。接口会对无 Key、鉴权失败、限流、超时、数据缺失等情况返回错误，不切换为模拟数据。

该接口直接调用问财 HTTP API，运行项目不要求安装问财 Skill 或 Python，但需要网络以及当前使用者有权限的问财 Key。Skill 安装与项目后端配置是两回事：对方应使用自己的 Key，配置在后端进程能够读取的环境或项目 `.env` 中，之后重启后端；还需要按模型模式说明配置模型服务 Key。

**目前这只是后端数据查询接口，并未接入看板。** 问财返回字段的成交量单位、价格复权口径与项目内展示许可尚待确认，接口故意将它们标为未确认，不能假定其数值单位。界面中的问财选项仍为“待接入”，本地模拟演示保持不变。单股真实接口请求成功，但尚未完成全部异常和数据口径验证；详见 [验证记录](需求文件/阶段三步骤1验证记录.md)。
